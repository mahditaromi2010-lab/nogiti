# گزارش فنی نسخهٔ توسعه‌یافتهٔ Nugiti / Nogiti

## نسخهٔ مبنا

مبنای کار `Nogiti-admin-security-branding-update.zip` از همین گفت‌وگو است. هیچ فایلی از مخزن خالی GitHub به‌عنوان منبع کد استفاده نشده است. بستهٔ لوگو و آیکون با `Nogiti-branding-kit.zip` مقایسه شد؛ لوگوی WebP، `favicon.ico`، آیکون ۱۹۲ پیکسل و Web App Manifest با بستهٔ برندینگ یکسان هستند.

## تغییرات

- ورود مستقل مدیر با نام کاربری و رمز عبور از `/admin/login` و ساختار جداگانهٔ `admin_accounts`.
- نقش‌های سمت سرور `owner`، `admin`، `content`، `orders` و `users`.
- صفحهٔ مدیریت حساب مدیران در `/admin/admins` برای مدیر اصلی و صفحهٔ اعتبارنامه‌های شخصی در `/admin/account`.
- هش رمز با bcrypt، حداقل طول ۱۲ نویسه در فرایندهای ایجاد/تغییر رمز، باطل‌سازی نشست با `session_version`، نشست مدیر با انقضای دو ساعته در صورت عدم فعالیت و حداکثر عمر ۱۲ ساعته.
- ثبت رویدادهای مدیریتی، حفظ CSRF/rate-limit و حفاظت سمت سرور برای مسیرهای مدیریت.
- مهاجرت سازگار برای انتقال هش مدیران قدیمی به ساختار جدید؛ نام کاربری تولیدشده برای حساب قدیمی `legacy_admin_<شناسه>` است و پس از ورود می‌توان آن را تغییر داد.
- تست‌های خودکار برای سیاست نقش‌ها، مسیرهای محافظت‌شده، اعتبارسنجی و ساختار مهاجرت.

## بررسی‌هایی که واقعاً اجرا شدند

- `npm run check`: موفق.
- بررسی نحوی Node.js برای سرور، ماژول مجوزها، اسکریپت مهاجرت، اسکریپت ساخت مدیر و فایل‌های JavaScript عمومی: موفق.
- `node --test`: ۶ تست موفق، ۰ ناموفق.
- مقایسهٔ فایل‌های لوگو و آیکون با بستهٔ برندینگ: تطابق بایتی.
- بررسی آرشیو ZIP و فهرست فایل‌ها: در مرحلهٔ بسته‌بندی انجام می‌شود.

## محدودیت‌های آزمون

- نصب وابستگی‌ها با `npm install` در این محیط به پایان نرسید و timeout شد؛ بنابراین `node_modules` یا `package-lock.json` جدید تولید نشده است.
- PostgreSQL، Docker و مرورگر آزمایشی در محیط موجود نبودند؛ مهاجرت SQL، اجرای HTTP، ورود واقعی، مدیریت نشست‌ها و عملیات CRUD با پایگاه داده به‌صورت end-to-end آزمایش نشده‌اند.
- تست‌های فعلی، آزمون‌های واحد و ساختاری هستند؛ آن‌ها جایگزین آزمون یکپارچهٔ پس از نصب وابستگی‌ها و راه‌اندازی PostgreSQL نیستند.
